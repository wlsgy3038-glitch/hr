# RSUPPORT 인성검사 시제품

비개발자도 파일을 열어 사용할 수 있도록 만든 인성검사 관리자/지원자 화면 시제품입니다.

## 바로 여는 방법

1. 이 폴더 전체를 그대로 보관합니다.
2. 관리자 화면은 `index.html`을 더블클릭해서 엽니다.
3. 지원자 화면은 `candidate.html`을 열거나, 관리자 상세 화면의 `접속링크 복사` 버튼으로 링크를 복사합니다.

## 장비를 옮길 때 꼭 챙길 파일

아래 파일은 모두 같은 폴더 안에 있어야 합니다.

- `index.html`
- `candidate.html`
- `app.js`
- `styles.css`
- `questions-data.js`
- `scoring_rules.json`
- `best_type_rules.json`
- `interpretation_db.json`
- `interview_question_db.json`
- `README.md`
- `final-verification.js`

폴더 이름은 바뀌어도 괜찮지만, 파일들을 흩어놓으면 화면이 깨질 수 있습니다.

## 장비 이동 시 중요한 메모

현재 데이터는 서버 DB가 아니라 브라우저 `localStorage`에 저장됩니다.

따라서 폴더 파일만 다른 장비로 옮기면 화면과 코드 구조는 유지되지만, 기존 PC 브라우저에 저장된 검사/대상자/응답 데이터는 자동으로 옮겨지지 않습니다.

장비를 옮길 때 반드시 기억해야 할 점:

- 파일 이동만으로 옮겨지는 것: 화면, 문항 원본, 채점 로직, 결과지 로직, 스타일
- 자동으로 옮겨지지 않는 것: 생성한 검사, 등록한 대상자, 지원자 응답, 검사완료 결과, 브라우저에 저장된 수정 문항
- 실제 운영 단계에서는 서버/DB를 붙여야 장비가 바뀌어도 데이터가 유지됩니다.
- 임시 시제품 상태에서 기존 데이터를 옮기려면 브라우저 저장소 데이터를 별도로 내보내는 기능이 필요합니다. 현재는 메모만 남겨둔 상태입니다.

## 현재 구현된 주요 기능

- 검사 생성: 검사명, 시작일, 마감일
- 검사 현황 목록
- 검사대상자 등록/수정/삭제
- 대상자 비밀번호 등록 및 지원자 로그인 검증
- 지원자 접속 화면
- 총 200문항 검사 진행
- 기본 문항 152개 + 검증문항 48개
- 지원자별 문항 랜덤 배치
- 동일 요인 연속 출제 방지
- Q143, Q144 주의확인 문항 30~70% 구간 배치
- 25분 제한시간
- 시간 종료 시 자동 제출
- 진행 중 새로고침/종료 후 재접속 시 이어서 응시
- 검사 완료 후 재응시 불가
- 접속 횟수 5회 제한
- 미응답률, 응답 시간, 반복 응답, 주의확인 기반 무효 처리
- 결과지 출력 및 다운로드 버튼
- BEST 유형, 인성 레벨, CWB, 신뢰도, 강점/약점, 종합 분석 표시

- 조직 공격성 수준
- BEST 유형
- 유형 설명
- 인성 종합 점수

- CWB 영역

## 핵심 출제 규칙

- 검사는 총 `200문항`으로 진행됩니다.
- 기본 문항 `152개`는 반드시 모두 1회씩 출제합니다.
- 검증문항 `48개`를 추가로 출제합니다.
- 검증문항은 동일 문항 반복이 아니라 의미가 유사한 문항입니다.
- 검증문항 대상 요인:
  - 책임감
  - 자기통제
  - 스트레스내성
  - 윤리
  - 협력
  - 충동성
  - 신뢰
- 지원자마다 문항 순서는 랜덤으로 배치합니다.
- 동일 factor 문항이 2개 이상 연속으로 나오지 않도록 배치합니다.
- 검증문항은 랜덤 위치에 삽입합니다.
- 원문항과 검증문항은 최소 `20문항 이상` 떨어지도록 배치합니다.
- Q143, Q144 주의확인 문항은 전체 진행률 기준 `30~70%` 구간 안에 배치합니다.
- 이미 응시를 시작한 지원자의 문항 순서는 중간에 바꾸지 않습니다.

## 응시 정책

- 제한시간은 `25분`입니다.
- 문항별 개별 제한시간은 없습니다.
- 응시 화면 상단에 남은 시간을 표시합니다.
- 시간이 종료되면 자동 제출됩니다.
- 자동 제출 시점까지 저장된 응답만 채점합니다.
- 응답 데이터는 실시간으로 임시 저장합니다.
- 브라우저 종료 또는 새로고침 후 재접속하면 이어서 응시할 수 있습니다.
- 단, `다음`을 누른 뒤에는 이전 문항으로 돌아갈 수 없습니다.
- 검사 완료 후에는 재접속 및 재응시가 불가합니다.
- 지원자 접속 횟수는 최대 `5회`까지 허용합니다.
- 6번째 접속부터는 차단합니다.

## 문항 응답 정책

- 모든 문항 응답을 권장합니다.
- 미응답 상태로 다음을 누르면 경고를 표시합니다.
- 경고 문구:
  - `응답하지 않은 문항이 있습니다. 미응답 문항은 결과 신뢰도에 영향을 줄 수 있습니다.`
- 사용자가 경고를 확인하면 미응답 상태로도 다음 문항으로 넘어갈 수 있습니다.
- 미응답 문항은 `3점`으로 대체하지 않습니다.
- 미응답 문항은 해당 요인 점수 계산에서 제외합니다.

예시:

- 책임감 문항 5개 중 `5, 4, 5, 4, 미응답`인 경우
- 계산식은 `(5 + 4 + 5 + 4) ÷ 4`입니다.

## 채점 규칙

- 모든 점수는 기본적으로 `10점 척도`로 변환합니다.
- 일반 항목은 문항 평균을 계산한 뒤 `문항평균 × 2` 방식으로 10점 척도화합니다.
- 역문항은 아래처럼 반전 계산합니다.
  - 1 → 5
  - 2 → 4
  - 3 → 3
  - 4 → 2
  - 5 → 1
- `reverse=true` 문항은 역채점합니다.
- `validation=true` 문항은 신뢰도 판단용으로 별도 분석합니다.
- 인재상과 Workstyle은 점수가 높을수록 긍정으로 봅니다.
- CWB는 점수가 높을수록 위험으로 봅니다.

## 점수 등급 규칙

- 1~2점: `VERY LOW`
- 3~4점: `LOW`
- 5~6점: `AVERAGE`
- 7~8점: `HIGH`
- 9~10점: `VERY HIGH`

## CWB 조직 공격성 규칙

CWB 영역:

- 충동성
- 반사회성
- 무책임

판정:

- 1~4점: 양호
- 5~6점: 주의
- 7~10점: 위험

## 신뢰도 규칙

### 응답 솔직성

대상 문항:

- Q136
- Q137
- Q138
- Q139
- Q140

위 문항에서 4점 이상 응답이 많으면 응답 왜곡 위험으로 판단합니다.

### 주의확인 문항

- Q143 정답: 3
- Q144 정답: 2

판정:

- 2개 모두 정답: 정상
- 1개 오답: 신뢰도 경고
- 2개 오답: 신뢰도 낮음

### 일관성 검증

- 원문항과 검증문항의 응답 차이를 비교합니다.
- 차이 0~2: 정상
- 차이 3 이상: 일관성 오류
- 일관성 오류가 누적되면 응답 신뢰도를 하향합니다.

## 미응답 규칙

- 전체 문항 중 미응답 비율을 계산합니다.
- 미응답 5% 이하: 정상 결과 생성
- 미응답 5% 초과: 신뢰도 하향
- 미응답 10% 초과: 결과 무효

미응답 5% 초과 시 결과지 문구:

- `일부 문항이 응답되지 않아 결과 해석의 정확도가 다소 제한될 수 있습니다.`

미응답 10% 초과 시 결과지 문구:

- `미응답 문항이 과도하게 많아 결과를 산출할 수 없습니다.`

## 결과 무효 조건

아래 조건 중 하나라도 충족하면 결과를 무효 처리합니다.

- 미응답 비율 10% 초과
- Q143, Q144 주의확인 문항 2개 모두 오답
- 응답 시간 5분 미만
- 동일 응답 반복률 90% 이상

결과 무효 시:

- 인성 레벨 = `I`
- BEST 유형 미산출
- 강점 미산출
- 약점 미산출
- 종합 분석은 해석 불가/추가 확인 필요 문구로 표시

결과지 상단 문구:

- `응답 신뢰도가 매우 낮아 결과를 해석할 수 없습니다.`

## 인성 종합점수 규칙

인성 종합점수는 아래 요소를 합산해 계산합니다.

- 인재상 평균 × 35%
- Workstyle 평균 × 35%
- `(10 - CWB 평균)` × 20%
- 신뢰도 점수 × 10%

단, 인재상과 Workstyle이 모두 낮은 경우 종합 레벨이 과도하게 높게 나오지 않도록 보정합니다.

## 인성 레벨 규칙

- 9.0 이상: S
- 8.0~8.9: A
- 7.0~7.9: A-
- 6.0~6.9: B
- 5.0~5.9: B-
- 4.0~4.9: C
- 3.0~3.9: D
- 0~2.9: F
- 신뢰도 낮음 또는 결과 무효: I

## BEST 유형 계산 규칙

BEST 유형은 아래 4개 축으로 계산합니다.

### T vs C

T 기준:

- 도전
- 창의
- 혁신
- 적응성/융통성

C 기준:

- 신뢰
- 윤리
- 책임감
- 꼼꼼함

### P vs A

A 기준:

- 성취지향성
- 자발성
- 리더십
- 도전

P는 A 성향이 낮은 경우의 상대 유형입니다.

### I vs O

O 기준:

- 사교성
- 대인이해
- 팀워크
- 협력

I 기준:

- 독립
- 분석적사고

### E vs R

E 기준:

- 충동성
- 사교성

R 기준:

- 자기통제
- 스트레스내성
- 윤리
- 책임감

## 강점/약점 추출 규칙

- 강점은 Workstyle 영역의 상위 3개 요인을 추출합니다.
- 약점은 Workstyle 영역의 하위 2개 요인을 추출합니다.
- 결과 무효 시 강점/약점은 제공하지 않습니다.

## 종합 분석 생성 규칙

결과지 하단에 `종합 분석` 영역을 표시합니다.

종합 분석은 아래 정보를 종합해 생성합니다.

- BEST 유형
- 인성 레벨
- 인재상 점수
- Workstyle 점수
- 강점 상위 3개
- 약점 하위 2개
- CWB 결과
- 신뢰도 결과

분석은 단순 점수 나열이 아니라 `어떤 사람인지`를 설명해야 합니다.

출력 형식:

- `[업무 스타일]`
- `[대인관계]`
- `[강점]`
- `[주의점]`
- `[종합 의견]`

작성 원칙:

- 점수값을 그대로 나열하지 않습니다.
- `성실하다`, `책임감이 있다` 같은 단순 표현만 반복하지 않습니다.
- 모든 결과를 긍정적으로만 작성하지 않습니다.
- 강점과 약점을 모두 언급합니다.
- 결과 무효 시 해석 불가/추가 확인 필요 문구로 표시합니다.

## PDF/출력 규칙

- 결과지 모달에서 `인쇄` 또는 `다운로드` 버튼을 사용할 수 있습니다.
- 현재 다운로드는 브라우저의 인쇄/PDF 저장 기능을 사용합니다.
- 실제 파일 자동 다운로드 방식은 아직 구현되어 있지 않습니다.

## 테스트 방법

개발 검증용으로 Node.js가 설치되어 있으면 아래 명령을 실행할 수 있습니다.

```powershell
node --check app.js
node final-verification.js
```

정상 결과:

- `node --check app.js`: 아무 오류 없이 종료
- `node final-verification.js`: `failedCount: 0`

## 주의사항

- 현재는 실제 서버가 붙어 있지 않습니다.
- 다른 PC나 모바일에서 동시에 접속해도 데이터가 자동 연동되지 않습니다.
- 실제 채용 운영용으로 쓰려면 서버/DB, 관리자 로그인, 외부 URL 배포, 개인정보 보안 처리가 필요합니다.
